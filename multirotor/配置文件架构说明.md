# 配置文件架构说明

## 📂 配置文件职责划分

为了避免配置冗余和复杂性，我们将配置文件按职责进行了分离：

### 1. `drones_config.json` - 无人机配置（核心）
**位置**: `multirotor/drones_config.json`

**职责**: 统一管理所有无人机的基础配置和训练选择

**包含内容**:
- 无人机列表及其基础信息（类型、启用状态、镜像模式）
- DQN 训练使用的无人机配置
- DDPG 训练使用的无人机配置

**示例配置**:
```json
{
  "drones": {
    "UAV1": {
      "enabled": true,
      "type": "virtual",
      "isCrazyflieMirror": false
    },
    "UAV2": {
      "enabled": true,
      "type": "physical",
      "isCrazyflieMirror": true
    }
  },
  "training": {
    "dqn": {
      "use_all_drones": false,
      "drone_list": ["UAV1"]
    },
    "ddpg": {
      "use_all_drones": true
    }
  }
}
```

**配置说明**:
- `enabled`: 是否启用该无人机
- `type`: `virtual` (虚拟无人机 AirSim) 或 `physical` (实体无人机 Crazyflie)
- `isCrazyflieMirror`: 是否为 Crazyflie 实体无人机的镜像（用于虚实协同）
- `use_all_drones`: 
  - `true` - 使用所有 `enabled=true` 的无人机
  - `false` - 使用 `drone_list` 指定的无人机
- `drone_list`: 指定训练使用的无人机名称列表

---

### 2. `movement_dqn_config.json` - DQN 算法配置
**位置**: `multirotor/DQN_Movement/configs/movement_dqn_config.json`

**职责**: 仅管理 DQN 算法相关的参数

**包含内容**:
- 移动参数（步长、最大步数）
- 奖励函数参数
- 阈值参数
- 训练超参数（学习率、批次大小等）
- 模型结构参数
- 评估参数

**不再包含**: ~~无人机配置（已移至 drones_config.json）~~

---

### 3. DDPG 训练配置文件
**位置**: `multirotor/DDPG_Weight/configs/`

**职责**: 仅管理 DDPG 算法相关的参数

**包含内容**:
- `unified_train_config.json` 中的模式化训练参数
- `crazyflie_reward_config.json` 中的权重环境奖励参数
- `legacy/` 中的历史配置样例

**不再包含**: ~~无人机配置（已移至 drones_config.json）~~

---

### 4. `apf_algorithm_config.json` - APF 算法配置
**位置**: `multirotor/apf_algorithm_config.json`

**职责**: APF 算法参数和网格配置

**包含内容**:
- APF 算法系数（吸引力、排斥力等）
- 网格数据配置
- 扫描区域参数

**说明**: 旧的混合式 `droneSettings` 配置思路已经废弃，当前不再建议把无人机选择写入 APF 配置。

## 🔧 使用方法

### Python 代码中使用

```python
from Algorithm.drones_config import DronesConfig

# 加载无人机配置
drones_config = DronesConfig()

# 获取所有无人机
all_drones = drones_config.get_all_drones()
print(f"所有无人机: {all_drones}")

# 获取启用的无人机
enabled_drones = drones_config.get_enabled_drones()
print(f"启用的无人机: {enabled_drones}")

# 获取 DQN 训练使用的无人机
dqn_drones = drones_config.get_training_drones('dqn')
print(f"DQN训练无人机: {dqn_drones}")

# 获取 DDPG 训练使用的无人机
ddpg_drones = drones_config.get_training_drones('ddpg')
print(f"DDPG训练无人机: {ddpg_drones}")

# 获取单个无人机信息
drone_type = drones_config.get_drone_type('UAV1')
is_crazyflie = drones_config.is_crazyflie_mirror('UAV1')
is_enabled = drones_config.is_enabled('UAV1')
```

### DronesConfig API 参考

#### 获取无人机列表
- `get_all_drones()` - 返回所有无人机名称列表
- `get_enabled_drones()` - 返回所有启用的无人机列表
- `get_training_drones(algorithm)` - 返回指定算法训练使用的无人机列表
  - `algorithm`: `'dqn'` 或 `'ddpg'`

#### 获取无人机信息
- `get_drone_info(drone_name)` - 返回指定无人机的详细信息字典
- `get_drone_type(drone_name)` - 返回无人机类型 (`'virtual'` 或 `'physical'`)
- `is_crazyflie_mirror(drone_name)` - 判断是否为实体无人机 (返回 `True/False`)
- `is_enabled(drone_name)` - 判断无人机是否启用 (返回 `True/False`)

#### 保存配置
- `save_config()` - 保存修改后的配置到文件

## 📝 修改训练使用的无人机

### 方式 1: 使用所有启用的无人机

编辑 `drones_config.json`:
```json
{
  "training": {
    "dqn": {
      "use_all_drones": true
    }
  }
}
```

### 方式 2: 指定特定无人机

编辑 `drones_config.json`:
```json
{
  "training": {
    "dqn": {
      "use_all_drones": false,
      "drone_list": ["UAV1", "UAV2"]
    }
  }
}
```

### 方式 3: 禁用某个无人机

编辑 `drones_config.json`:
```json
{
  "drones": {
    "UAV2": {
      "enabled": false,
      "type": "virtual",
      "isCrazyflieMirror": false
    }
  }
}
```

## ✨ 架构优势

### 1. 职责清晰
每个配置文件只管理自己领域的参数：
- `drones_config.json` → 无人机硬件配置
- `movement_dqn_config.json` → DQN 算法参数
- DDPG 配置文件 → DDPG 算法参数
- `apf_algorithm_config.json` → APF 算法参数

### 2. 避免冗余
无人机配置只需在一个地方定义，所有训练脚本共享同一配置源。

### 3. 易于扩展
- 添加新无人机：只需修改 `drones_config.json`
- 添加新算法：创建新的算法配置文件，无需重复定义无人机

### 4. 统一管理
DQN 和 DDPG 共享同一个无人机配置源，保证一致性。

### 5. 灵活切换
通过修改配置文件轻松切换训练使用的无人机，无需修改代码。

## 📌 注意事项

### 1. DQN 多智能体支持
**当前 DQN 支持两种训练模式**：
- **单机训练**：配置 1 个无人机时，使用 `MovementEnv`
- **多机训练（参数共享）**：配置多个无人机时，使用 `MultiDroneMovementEnv`
  - 多个无人机轮流执行动作
  - 共享同一个 DQN 模型参数
  - 所有无人机学习相同的策略
  - 适合同质化多机协同任务

系统会根据 `drones_config.json` 中配置的无人机数量自动选择环境类型。

### 2. DDPG 多智能体支持
DDPG 支持多无人机协同训练，可以配置多个无人机。

### 3. 配置验证机制
`DronesConfig` 类会自动验证：
- 无人机是否存在于配置中
- 无人机是否已启用
- 无效配置会被跳过并给出警告

### 4. 向后兼容
`apf_algorithm_config.json` 曾承担过部分无人机配置职责；相关 `droneSettings` 思路已废弃，新代码不应再回到这种混合配置方式。

### 5. 配置文件位置
主配置集中在 `multirotor/` 与算法子目录的 `configs/` 下，便于统一管理。

## 🎯 最佳实践

### 1. 集中管理无人机配置
所有无人机的添加、修改、删除都在 `drones_config.json` 中进行。

### 2. 使用 DronesConfig 类
在代码中始终使用 `DronesConfig` 类而不是直接读取 JSON 文件。

### 3. 验证配置有效性


### 4. 保持配置同步
修改无人机配置后，确保所有训练脚本都能正确读取新配置。

### 5. 文档更新
添加新无人机时，更新项目文档说明其用途和配置。

## 🔍 故障排查

### 问题 1: 训练脚本找不到无人机

**症状**: 错误信息 "没有可用的训练无人机"

**排查步骤**:
1. 检查 `drones_config.json` 中无人机是否已启用 (`enabled: true`)
2. 如果 `training.dqn.use_all_drones` 为 `false`，检查 `training.dqn.drone_list` 中的无人机名称是否正确
3. 检查无人机名称拼写是否与 `drones` 块中定义的一致

### 问题 2: 配置修改不生效

**症状**: 修改配置后训练仍使用旧配置

**排查步骤**:
1. 确认修改的是正确的配置文件（`drones_config.json`）
2. 检查 JSON 格式是否正确（使用 JSON 验证工具）
3. 重启训练脚本，确保重新加载配置

### 问题 3: 虚实混合配置错误

**症状**: 实体无人机被识别为虚拟无人机（或反之）

**排查步骤**:
1. 检查 `isCrazyflieMirror` 字段是否正确设置
2. 确认 `type` 字段与实际硬件类型一致
3. 使用 `drones_config.get_drone_info()` 验证配置
